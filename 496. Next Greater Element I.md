[496. Next Greater Element I](https://leetcode.com/problems/next-greater-element-i/)

The **next greater element** of some element `x` in an array is the **first greater** element that is **to the right** of `x` in the same array.

You are given two **distinct 0-indexed** integer arrays `nums1` and `nums2`, where `nums1` is a subset of `nums2`.

For each `0 <= i < nums1.length`, find the index `j` such that `nums1[i] == nums2[j]` and determine the **next greater element** of `nums2[j]` in `nums2`. If there is no next greater element, then the answer for this query is `-1`.

Return _an array_ `ans` _of length_ `nums1.length` _such that_ `ans[i]` _is the **next greater element** as described above._

**Example 1:**

**Input:** nums1 = [4,1,2], nums2 = [1,3,4,2]
**Output:** [-1,3,-1]
**Explanation:** The next greater element for each value of nums1 is as follows:
- 4 is underlined in nums2 = [1,3,4,2]. There is no next greater element, so the answer is -1.
- 1 is underlined in nums2 = [1,3,4,2]. The next greater element is 3.
- 2 is underlined in nums2 = [1,3,4,2]. There is no next greater element, so the answer is -1.

**Example 2:**

**Input:** nums1 = [2,4], nums2 = [1,2,3,4]
**Output:** [3,-1]
**Explanation:** The next greater element for each value of nums1 is as follows:
- 2 is underlined in nums2 = [1,2,3,4]. The next greater element is 3.
- 4 is underlined in nums2 = [1,2,3,4]. There is no next greater element, so the answer is -1.

**Constraints:**

- `1 <= nums1.length <= nums2.length <= 1000`
- `0 <= nums1[i], nums2[i] <= 104`
- All integers in `nums1` and `nums2` are **unique**.
- All the integers of `nums1` also appear in `nums2`.

**Follow up:** Could you find an `O(nums1.length + nums2.length)` solution?

## brute force

```python
class Solution:
    def nextG(self, j, nums2):
        temp = nums2[j]
        k = j + 1

        while k < len(nums2):
            if nums2[k] > temp:
                return nums2[k]
            k += 1

        return -1

    def nextGreaterElement(self, nums1: List[int], nums2: List[int]) -> List[int]:
        res = []

        for i in nums1:
            j = 0
            while j < len(nums2):
                if i == nums2[j]:
                    res.append(self.nextG(j, nums2))
                    break
                j += 1

        return res
```

## optimal

```python
class Solution:
    def nextGreaterElement(self, nums1: List[int], nums2: List[int]) -> List[int]:
        ng = {}
        stack = []

        for i in nums2:
            while stack and  i > stack[-1]:
                ng[stack.pop()] = i
            stack.append(i)
        
        while stack:
            ng[stack.pop()] = -1

        res = []
        for i in nums1:
            res.append(ng[i])

        return res
```



The key idea is to use a **monotonic decreasing stack**. Let's understand **why** it works.

---

## Brute Force (Not Optimal)

For every element in `nums1`:

1. Find its position in `nums2`.
    
2. Scan to the right until you find a larger element.
    

Example:

```python
nums1 = [2,4]
nums2 = [1,2,3,4]
```

For `2`:

```
1  2  3  4
   ^
Look right:
3 > 2  ✓
Answer = 3
```

For `4`:

```
1  2  3  4
         ^
Nothing larger
Answer = -1
```

This can take **O(n²)** in the worst case.

---

# Better Idea

Instead of searching to the right for every number repeatedly, preprocess `nums2` once.

We'll create a dictionary:

```python
{
    element : next_greater_element
}
```

Then answering for `nums1` is just dictionary lookups.

The question becomes:

> How do we build this dictionary efficiently?

This is where the stack helps.

---

# Why a Stack?

Suppose we're reading

```
nums2 = [1,3,4,2]
```

We'll keep a stack of numbers that **haven't found their next greater element yet**.

Initially

```
Stack = []
```

Meaning:

> "We still don't know the next greater element for 1."

```

Yes!

```

```

Store it.

```

```

Pop 1.

Stack becomes

```
[]
```

Now push 3.

```

```

Now 3 is waiting for its next greater element.

## Step 3: Read 4

Top is

```
3
```

Is

```
4 > 3 ?
```

Yes.

So

```
3 -> 4
```

Store

```

    1:3,
    3:4
}
```

Pop 3.

```

---

## Step 4: Read 2

Top is

```

```

```

No.

```

The stack still contains

These numbers never found a larger element.

    2:-1

```

2 -> -1

```

# Why is the stack decreasing?

Notice what happens.

```
Stack = [4,2]
```

Top is always the **smallest** among the stack.

From bottom to top:

```
4
2
```

It is decreasing.

Whenever a larger element arrives, it removes all smaller elements from the top.

Example:

```
Stack

8
6
5
3
```

New number is

```
7
```

Compare:

```
7 > 3  pop
7 > 5  pop
7 > 6  pop
7 > 8  no
```

Now push 7.

```
8
7
```

Still decreasing.

This is why it's called a **monotonic decreasing stack**.

---

# Why is it O(n)?

Each element is:

- pushed **once**
    
- popped **once**
    

For example,

```
1 3 4 2
```

Operations:

```
1 -> push
1 -> pop

3 -> push
3 -> pop

4 -> push
4 -> pop (or remain until the end)

2 -> push
2 -> pop (at the end)
```

Even though there is a `while` loop, an element cannot be popped more than once.

So the total number of stack operations is at most:

- `n` pushes
    
- `n` pops
    

Therefore, the overall time complexity is **O(n)**, making this the optimal solution.


This is the **core** of the algorithm. Let's break it down line by line.

```python
while stack and num > stack[-1]:
    next_greater[stack.pop()] = num
```

### `stack and num > stack[-1]`

This checks two things:

1. `stack`
    
    - Is the stack non-empty?
        
    - We can't access `stack[-1]` if it's empty.
        
2. `num > stack[-1]`
    
    - Is the current number greater than the number on the top of the stack?
        

If both are true, we've found the **next greater element** for the top of the stack.

## Why a `while` and not an `if`?

Imagine:

```python
stack = [8, 6, 5, 3]
num = 7
```

The new number `7` is greater than **multiple** elements.

It is the next greater element for:

- 3 ✓
    
- 5 ✓
    
- 6 ✓
    

but **not** for 8.

The `while` loop pops all of them:

```
Before:
Stack = [8, 6, 5, 3]

7 > 3  → pop, map 3 → 7
Stack = [8, 6, 5]

7 > 5  → pop, map 5 → 7
Stack = [8, 6]

7 > 6  → pop, map 6 → 7
Stack = [8]

7 > 8  → false, stop

Push 7

Stack = [8, 7]
```

If you had used `if` instead of `while`, only `3` would be processed, and `5` and `6` would incorrectly remain waiting.

So this code is repeatedly saying:

> "As long as the current number is greater than the top of the stack, we've found the next greater element for that top element. Record it, remove it, and check the next one."
