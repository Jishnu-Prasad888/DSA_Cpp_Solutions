### optimised binary search

```cpp
#include <vector>
#include <algorithm>
using namespace std;

class Solution {
public:
    int countLessEqual(const vector<vector<int>>& matrix, int mid) {
        int n = matrix.size();
        int count = 0;
        int row = n - 1, col = 0; // Start from bottom-left

        while (row >= 0 && col < n) {
            if (matrix[row][col] <= mid) {
                count += row + 1; // All elements in this column up to current row are <= mid
                col++;
            } else {
                row--;
            }
        }
        return count;
    }

    int kthSmallest(vector<vector<int>>& matrix, int k) {
        int n = matrix.size();
        int left = matrix[0][0], right = matrix[n - 1][n - 1];

        while (left < right) {
            int mid = left + (right - left) / 2;
            if (countLessEqual(matrix, mid) < k) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }
        return left;
    }
};
```

##### **note : l<r not <=**

✅ **Time Complexity:** `O(n log(max-min))`  
✅ **Space Complexity:** `O(1)`

### **Why `right = mid` and not `mid + 1`?**

1. **Goal:** find the **smallest value** `x` such that there are **at least k elements ≤ x**.
2. **Case:** `countLessEqual(mid) >= k`
    - This means `mid` **could be the answer**, but maybe there’s a smaller value that also satisfies it.
    - If we did `right = mid - 1`, we would **skip over mid**, possibly missing the correct answer.
3. **Correct move:**
    - Keep `mid` in the search space → `right = mid`
    - Eventually, `left == right` → smallest value with ≥ k elements ≤ it → exactly k-th smallest.

### **Case for `left = mid + 1`**
 
- We only do `left = mid + 1` when we know **mid is too small**.
- That is, `countLessEqual(mid) < k` → not enough elements ≤ mid → kth element is strictly bigger than mid.

### **Matrix Example**

Suppose we have this sorted 4x4 matrix:

```
1   5   9   10
2   6   11  15
3   7   12  16
4   8   13  17
```

We want to **count how many elements ≤ mid = 10**.

Absolutely! Here’s an **ASCII diagram** showing the **bottom-left traversal** for counting elements ≤ mid in a 4x4 matrix.

Suppose the matrix is:

```

2   6   11  15
3   7   12  16
4   8   13  17
```

We want to count elements ≤ 10.

```

Move right

[1]  5   9   10
[2]  6   11  15
[3]  7   12  16
4   8  [13] 17  <- 13 > 10 ❌ move up

[1]  5   9   10
[2]  6  [11] 15  <- 11 > 10 ❌ move up
[3]  7   12  16
4   8   13  17

[1]  5  [9]  10  <- 9 <= 10 ✅ count += 1
[2]  6   11  15

```

---

### **Key Idea in the Diagram**

- Start **bottom-left**.
- **If ≤ mid:** add all above and move **right**.
- **If > mid:** move **up**.
- Stop when you go **out of bounds**.
    

This traversal ensures you **visit only O(n) elements** instead of O(n²).



## Optimised approach min heap :


```cpp
#include <vector>
#include <queue>
using namespace std;

class Solution {
public:
    struct Node {
        int val;
        int r, c;
        Node(int v, int i, int j) : val(v), r(i), c(j) {}
        bool operator>(const Node& other) const {
            return val > other.val; // min-heap
        }
    };

    int kthSmallest(vector<vector<int>>& matrix, int k) {
        int n = matrix.size();
        priority_queue<Node, vector<Node>, greater<Node>> pq;

        // Push the first element of each row (up to k rows)
        for (int i = 0; i < n && i < k; i++) {
            pq.push(Node(matrix[i][0], i, 0));
        }

        Node cur(0, 0, 0);
        for (int i = 0; i < k; i++) {
            cur = pq.top();
            pq.pop();
            int r = cur.r, c = cur.c;
            if (c + 1 < n) {
                pq.push(Node(matrix[r][c + 1], r, c + 1));
            }
        }
        return cur.val;
    }
};

```


✅ **Time Complexity:** `O(k log n)`  
✅ **Space Complexity:** `O(min(n, k))`
