[1901. Find a Peak Element II](https://leetcode.com/problems/find-a-peak-element-ii/)

A **peak** element in a 2D grid is an element that is **strictly greater** than all of its **adjacent** neighbors to the left, right, top, and bottom.

Given a **0-indexed** `m x n` matrix `mat` where **no two adjacent cells are equal**, find **any** peak element `mat[i][j]` and return _the length 2 array_ `[i,j]`.

You may assume that the entire matrix is surrounded by an **outer perimeter** with the value `-1` in each cell.

You must write an algorithm that runs in `O(m log(n))` or `O(n log(m))` time.
### optimised

```cpp
class Solution {
public:
    vector<int> findPeakGrid(vector<vector<int>>& mat) {
        int m = mat.size();
        int n = mat[0].size();
        int left = 0, right = n - 1;

        while (left <= right) {
            int midCol = left + (right - left) / 2;

            // find the max element in midCol
            int maxRow = 0;
            for (int i = 0; i < m; i++) {
                if (mat[i][midCol] > mat[maxRow][midCol]) {
                    maxRow = i;
                }
            }

            int leftVal = (midCol - 1 >= 0) ? mat[maxRow][midCol - 1] : -1;
            int rightVal = (midCol + 1 < n) ? mat[maxRow][midCol + 1] : -1;

            if (mat[maxRow][midCol] > leftVal && mat[maxRow][midCol] > rightVal) {
                // peak found
                return {maxRow, midCol};
            } else if (mat[maxRow][midCol] < rightVal) {
                left = midCol + 1; // move right
            } else {
                right = midCol - 1; // move left
            }
        }

        return {-1, -1}; // should never reach here
    }
};

```


Ah! I see exactly what you’re thinking. Let’s reason carefully.

You said: **“all the rows are strictly increasing”**. That changes things a bit. But let’s check carefully:

1. **Matrix property in the original problem (1901):**
    
    - There is **no requirement that rows are sorted or strictly increasing**.
        
    - The only given guarantees are:
        
        - No two adjacent cells are equal.
            
        - Peak is strictly greater than neighbors.
            
2. **If hypothetically all rows are strictly increasing**:
    
    - Then, in any row, the **last element is the largest in that row**.
        
    - So the **maximum in a column** may not even be at the last element—still, the middle column could have its **column maximum anywhere in the row**.
        
    - You **cannot ignore the neighbors left and right**, because a peak requires **strictly greater than left and right neighbors**, not just being a column max.
        
    
    For example:
    
    ```
    row1: 1  3  5
    row2: 2  4  6
    row3: 0  2  3
    ```
    
    - Suppose you pick `midCol = 1` (second column).
        
    - Maximum in column 1 is 4 at row 2.
        
    - Left neighbor = 2, Right neighbor = 6.
        
    - 4 is **not a peak**, even though it’s column max.
        

✅ So you **still need to compare left/right neighbors**, even if the rows are strictly increasing.

---

**Key takeaway:**

- Column maximum **alone** does **not guarantee a peak**.
    
- You must check **horizontal neighbors** to decide which direction to move during binary search.
